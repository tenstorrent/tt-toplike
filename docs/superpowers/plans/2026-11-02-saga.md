# Saga Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A generative quest view, fed only by the signal bus, where a hero quests through dungeons that the machine's signals build, destroy and rebuild, with a deterministic core, a chronicle, and (later) monsters, NPCs, treasure and events published back to the bus.

**Architecture:** A pure, deterministic library crate `crates/tt-toplike-saga` turns an ordered stream of bus `Record`s into a world state and saga events. A driver thread in the root crate feeds it from the bus. A TUI view draws the state. Phase 0 first merges the three copies of the history-and-away rule into one module so views share one intake.

**Tech Stack:** Rust 2021 (MSRV 1.93), ratatui 0.30, the existing `tt-toplike-bus` crate. The core uses no external randomness crate: its own PCG generator, so results never depend on a dependency version.

**Spec:** `docs/superpowers/specs/2026-11-02-saga-design.md`. This plan covers phase 0 and phase 1 in full tasks and phase 2 as task outlines. Phases 3 and 4 (steering, arcade panel, packs, glitch terrain, narrator) get their own plan after phase 1 ships, because the view's real needs will shape them.

## Global Constraints

- **Determinism contract (spec 3.5):** the same ordered stream of record contents gives the same saga. The core reads no sequence number and no timestamp for any decision. Its clock is the number of "pacemaker" sweeps it has seen.
- **Pure core:** `tt-toplike-saga` depends only on `tt-toplike-bus` (for `Record`, `Payload`, `Event`, `EntityKey`, `EntityKind`, `Value`) and `serde` if needed. No `std::time`, `std::env`, `std::fs`, `std::thread`, no terminal, no OS randomness. A `clippy.toml` with `disallowed-methods` and `disallowed-types` enforces it (`Instant::now`, `SystemTime::now`, `std::env::var`, `HashMap`, `HashSet`: use `BTreeMap` and `BTreeSet` so iteration order is fixed).
- **Platform-stable arithmetic:** inside the core use only `+ - * /`, comparisons, `sqrt` and integer operations. No `sin`, `cos`, `exp`, `powf`, `ln`, which can differ between platforms. `#![forbid(unsafe_code)]`.
- **Budgets (spec 9):** a simulation step costs under 1 ms; grid at most 120 x 60 cells; at most 500 entities; chronicle ring of 500 lines; quiet-world terminal traffic under 20 KB/s at 140x40.
- **Privacy (spec 10):** a command line never appears anywhere in the saga. A process appears only by its process name. `names = "generated"` leaves no real name.
- **Provenance:** every beat names a cause (entity, signal, stream ordinal). Fiction is decoration; a monster from a measured signal always has a real cause. Mock runs say "(mock)", replays "(replay)".
- **Repository rules:** plain-English prose in docs, comments and text a person reads (run the sweep for `, not `, `rather than`, `instead of`, `reads as`, `honest`, `the one`, `which is why`, `This is what`); no right-side border characters; bump the version with each change (the root crate goes to 0.16.0 when phase 1 lands); default branch `main`; no hardware; never `pgrep -f`/`pkill -f`.
- **Tests:** fixed clocks and fixed inputs only (the box is loaded, so a wall-clock assertion is a defect). Every pinned golden (Die 3D, `i`, arcade, backdrop, every empty-world one) stays byte-identical. Before a task is done, run the CI forms in `.github/workflows/ci.yml` and the lib tests the way CI does (`env -u COLORTERM -u TMUX TERM=dumb cargo test --locked --lib --features tui`). A test that has never been seen to fail is a claim, not a check: put each guarded bug back once and confirm red.
- **Words:** the lexicon comes from the spec (7.1): Tenstorrent chip and product names, AI and ML terms, and real model and process names. Brand palette: dark forest teal `#092221`, blue `#1B8EB1`, teal `#74C5DF`, green `#6FABA0`, yellow `#F6BC42`, orange `#FA512E`.

## Review Focus

The places most likely to bite a person using this, most likely first. Each has a test in the task that owns the code.
1. **Live and replay disagree.** A sequence number, timestamp or hash-map order leaks into a decision, so a replayed log tells a different story. (Tasks 1.3, 1.5, 1.12.)
2. **The hero gets stuck, or a room is unreachable,** on odd topologies: zero chips, one chip, a fully harvested die, a 32-chip box. (Tasks 1.7, 1.9.)
3. **A quiet machine gives a dead view,** or worlds never end, or the cycle stalls. (Tasks 1.8, 1.12.)
4. **A command line or real name leaks into the chronicle** with `names = "generated"`, or at all. (Task 1.10.)
5. **Cost:** CPU or terminal traffic grows without bound with chips, entities or terminal size, or the view panics at 0x0 or 500x200. (Tasks 1.7, 1.14.)

They follow the spec's tables.
