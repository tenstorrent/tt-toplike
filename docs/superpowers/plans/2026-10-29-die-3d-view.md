# Die 3D View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new terminal view (`3`) that draws the board and its die(s) in faked-3D isometric perspective with braille characters, driven by passive telemetry, with signal-triggered camera cuts and a one-board and an every-board scene.

**Architecture:** A software rasteriser draws an isometric scene into an RGB pixel buffer. A converter turns the buffer into ratatui lines (braille 2x4 per cell, half-block 1x2 as fallback). A `Die3dView` owns scene choice, camera and trigger state and follows the same `new` / `update` / `render` shape as `TrainView`. The view is wired into `DisplayMode` as an entry-key-only mode. Per-tile counters (tier 1) are a separate plan; this plan leaves one input slot for them and labels the glow an estimate.

**Tech Stack:** Rust, ratatui 0.30, existing `TelemetryBackend` trait, `BoardTopology`, `AdaptiveBaseline`. One Python script run once against hardware (tt-exalens 0.4.2, in `~/.venvs/tt-exalens-latest`) to generate the Blackhole layout table.

**Spec:** `docs/superpowers/specs/2026-10-29-die-3d-view-design.md` (mockups in `docs/superpowers/specs/assets/2026-10-29-die-3d/`; the rasteriser and braille conversion in `die-3d-resolution.html` are the reference).

## Global Constraints

- Terminal output: left-side and bottom bars only, no right-side border characters.
- Truecolour output. Braille is the 3D mode; half-block (`▀`) is the fallback.
- Reference size: 150 x 42 cells (300 x 168 braille dots). Minimum offered size: 100 x 30 cells.
- Blackhole only in this version; other architectures show a one-card hint.
- Tier 0 only: sysfs, hwmon, smbus telemetry, PCIe counters. Anything estimated is labelled on screen.
- Never read ARC, PCIe, L2CPU or security tile registers (applies to the layout generator too).
- Hardware use needs a gozer lease (`gozer acquire --chips 1 --who claude:tt-toplike ...`). Release by lease id; if release is refused with "device still open", retry when `pids_holding` is empty.
- Bump the version with each change. This work is 0.13.19 (the PCIe fix is 0.13.18).
- Test commands: `cargo test --locked --lib --features tui`; `cargo clippy --locked --lib --bin tt-toplike-tui --features tui -- -D warnings`. Bare `cargo test` fails on the `gui_concept` example (needs `iced`); that predates this work.
- Comments explain the why and are kept true to the code (global CLAUDE.md).

## Review Focus

- A terminal smaller than 100 x 30: the view shows a hint and does not panic.
- No devices, one chip, or chips with no telemetry: the view renders and does not panic.
- A Wormhole or Grayskull device in the list: a hint card for that chip, no Blackhole layout applied to it.
- A resize while a camera cut is in progress: buffers are rebuilt at the new size and nothing indexes out of bounds.
- A missing, NaN or infinite PCIe rate, or a counter reset: no stream drawn and no NaN reaches a colour or index.

  - `pub fn chip_inputs(backend: &dyn TelemetryBackend, device: &Device) -> ChipInputs`: `load = power_w / tdp` clamped to 0..1, where tdp is `smbus.tdp_watts()` else `device.limits.tdp_limit` (as `TrainView::chip_tdp` does), `0.0` when unknown; `gddr_heat = ((max_gddr_temp_computed - 40) / 50).clamp(0, 1)`; `eth_live` from `SmbusTelemetry.eth_live_status` (`0` when absent); PCIe from `backend.pcie_bandwidth(idx)`; `enabled_tensix_col` from the same smbus field the portrait uses (`tensix_col_harvested`'s mask).

Packets are only drawn when the rate is `Some`, finite and above 1 kB/s.

### Task 19: Calibrate activity to each chip's own idle

**Interfaces:**
- `pub struct LoadScale` with `new() -> LoadScale` and `observe(&mut self, now: f64, power_w: Option<f32>) -> f32`. It keeps one sample per second of view time for the last 600 seconds. `idle` is the minimum and `peak` the maximum of that window; `span = max(peak - idle, 25.0)` watts; the result is `((power - idle) / span).clamp(0.0, 1.0)`. Until 5 samples exist the result is `0.0`. A `None`, NaN or infinite power, or a `now` that goes backwards, does not change the window and returns the previous result. A call less than one second after the last sample returns the previous result.
- `chip_inputs` stays stateless: its `load` (power over limit) is the fallback. `Die3dView` holds one `LoadScale` per chip index and overrides `ChipInputs.load` with the relative value once the scale has 5 samples; the scene's tile heat, `Clouds` intensity (Task 17) and the `TriggerDetector` all read the overridden value.
